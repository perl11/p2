# use perl6 — Perl 6 Syntax

## Overview

p2 stands for two perls, perl5 and perl6 (hence 5+6=11).
There should be a unified p2 syntax, closer to p5 than the p6 incompatible changes.

But there should be seperate p5 and p6 parsers and run-times, to be able to run
existing .pl and .p6/.raku files.

p2 supports Perl 6 syntax blocks via the `use p6` pragma or a `-6` cmdline switch,
using the [pvip](https://github.com/tokuhirom/pvip) parser (`syn/syntax-p6.y`).

```perl
use p6 { say "Hello, World!" }   # block form: parse this block with p6 syntax

use p6;                          # whole-file form: rest of file is p6
say "Hello, World!"

p2 -6 -e'say "Hello, World!"'    # cmdline
```

## Architecture

```
use p6 { raw_text }
     |
     v
syntax-p5.y  --captures raw text as PN_STR-->  AST_MSG(PN_p6, raw)
     |
     v
compile.c  --dlopen libsyntax-p6.so-->  syntax_parse(P, raw, file)
     |
     v
syn/pvip_to_pn.c  --pvip parser + translator-->  PVIPNode* -> PNSource (PN)
     |
     v
compile.c  --existing compiler, unchanged-->  PNProto bytecode
     |
     v
VM  --method dispatch calls into libp6 runtime-->  p6_range(), p6_junc_and(), ...
```

Each `use p6` boundary produces a separately compiled unit (proto) that
is CALLed from the surrounding p5 code. Variables cross the boundary via the
shared lobby (globals); locals do not.

## PVIP Node Coverage

~70% of PVIP nodes map directly to existing PNSource AST nodes (arithmetic,
comparisons, control flow, functions, basic OOP). The remaining ~30% are
p6-specific features that translate to `p6_*` runtime calls dispatched into
`libp6`:

| Category | Nodes | Handling |
|----------|-------|----------|
| Literals, arithmetic, logic | INT, NUMBER, STRING, ADD, SUB, … | Direct PNSource mapping |
| Control flow | IF, ELSIF, ELSE, WHILE, FOR, RETURN, … | Direct PNSource mapping |
| Functions / closures | FUNC, LAMBDA, PARAMS, FUNCALL | Direct PNSource mapping |
| Basic OOP | CLASS, METHOD, METHODCALL | Direct PNSource mapping |
| Inplace ops | INPLACE_ADD, INPLACE_SUB, … | Expand to ASSIGN + op |
| Ranges / sequences | RANGE, SEQUENCE, REDUCE | `p6_range()`, `p6_seq()`, `p6_reduce()` |
| Junctions | JUNCTIVE_AND/OR/SAND | `p6_junc_and()`, `p6_junc_or()` |
| Roles / traits | ROLE, IS, DOES, HAS, AUGMENT | `p6_role()`, `p6_is()`, … |
| Regex | REGEXP, PERL5_REGEXP, SMART_MATCH | `p6_regexp()`, `p6_smartmatch()` |
| Special vars | TW_VM, TW_OS, TW_PID, … | `p6_vm()`, `p6_os()`, … |
| Whatever / stub | WHATEVER, STUB | `p6_whatever()`, `p6_stub()` |
| Misc p6 ops | Z, MINMAX, GCD, LCM, IS_DIVISIBLE_BY | `p6_zip()`, `p6_minmax()`, … |

## Files

| File | Purpose |
|------|---------|
| `syn/syntax-p5.y` | Grammar: `use perl6 { }` rule + `syntax-block` |
| `syn/pvip_to_pn.c` | Translator: `PVIPNode*` → `PNSource` (PN) + `syntax_parse` export |
| `syn/syntax-p6.y` | pvip PEG grammar (pre-existing) |
| `lib/potion/libsyntax-p6.so` | Dynamic library: pvip parser + translator |
| `core/compile.c` | `PN_perl6` AST handler: dlopen + translate + compile inline |
| `core/internal.c` | `PN_perl6` symbol declaration and initialization |
| `core/p2.h` | `extern PN PN_perl6` |

## Runtime Library (libp6, in work)

The `p6_*` functions called by translated code runs the p6 runtime library
(`lib/p6/libp6.so`) that registers these functions into the p2 lobby at load
time via `Potion_Init_libp6(Potion *P)`. This is where p6 semantics live:
junctions, `Whatever`, typed parameters, roles, grammars, etc.

## Limitations

- Locals do not cross the `use p6` boundary (different compiler layouts. Are they?
  The compiler is the same, only the parser and run-time not)
- The `syntax-block` raw-text capture does not handle `}` inside string literals
- `use p6;` (whole-file form) terminates the p5 parse at that point; mixed
  p5/p6 at statement level within one file is not supported
- The libp6 runtime is not yet implemented; `p6_*` calls will fail until it is
